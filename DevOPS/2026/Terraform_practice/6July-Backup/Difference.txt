==============================================================================
Terraform Module Design Patterns
==============================================================================

There are two common ways to use for_each with Terraform Modules.

==============================================================================
OPTION 1 : for_each ON MODULE (Module Iteration)
==============================================================================

Architecture

terraform.tfvars
        │
        ▼
Parent Module (for_each)
        │
        ├── Module Instance 1
        │        │
        │        ▼
        │     Resource (One Resource)
        │
        ├── Module Instance 2
        │        │
        │        ▼
        │     Resource (One Resource)
        │
        └── Module Instance N
                 │
                 ▼
              Resource (One Resource)

Flow

terraform.tfvars
        │
        ▼
Parent Module (for_each)
        │
        ▼
Multiple Child Module Instances
        │
        ▼
Each Child Module Creates One Resource

Characteristics

✔ Parent module performs the iteration.
✔ Child module is called multiple times.
✔ Each child module creates only one resource.
✔ Child module does NOT use for_each.
✔ Parent passes individual values to each module instance.

Example

NIC-01  →  Module Instance 1  →  One NIC

NIC-02  →  Module Instance 2  →  One NIC

NIC-03  →  Module Instance 3  →  One NIC

Advantages

✔ Good when every resource is independent.
✔ Easier to manage individual resources.
✔ Individual module instances can be targeted.
✔ Suitable for reusable enterprise modules.

Disadvantages

✘ Parent module becomes larger.
✘ More module instances.
✘ More variable mapping.
✘ More complex outputs.

==============================================================================

OPTION 2 : for_each INSIDE CHILD MODULE (Resource Iteration)
==============================================================================

Architecture

terraform.tfvars
        │
        ▼
Parent Module (One Call)
        │
        ▼
Child Module
        │
        ▼
Resource (for_each)
        │
        ▼
Multiple Resources

Flow

terraform.tfvars
        │
        ▼
Parent Module
        │
        ▼
One Child Module
        │
        ▼
Resource iterates using for_each

Characteristics

✔ Parent module calls the child module only once.
✔ Child module performs the iteration.
✔ Resource block uses for_each.
✔ Parent passes the complete map.
✔ Child creates all resources.

Example

Subnet Module

↓

One Child Module

↓

Creates

AzureBastionSubnet

snet-web01

snet-web02

Advantages

✔ Less code in parent module.
✔ Cleaner architecture.
✔ Easier for beginners.
✔ Easier output management.
✔ Consistent module structure.

Disadvantages

✘ Cannot independently target each module instance.
✘ Entire module is treated as one unit.
