========================================================================================================================
Important Fields Inside spec
========================================================================================================================

The spec section defines how the Service works. The four most important fields inside spec are:

1. selector
   → Finds the correct Pods using Labels.

2. ports
   → Defines the networking configuration of the Service.

3. targetPort
   → Specifies the port on which the application is running inside the Pod.

4. type
   → Defines how the Service can be accessed (Internal or External).

Together these four fields tell Kubernetes:

✔ Which Pods should receive traffic?
✔ Which port should receive the request?
✔ Which application port inside the Pod should handle the request?
✔ How users can access the Service?

========================================================================================================================
Overall Flow
========================================================================================================================

              Client
                 │
                 ▼
             Service
                 │
         ┌───────────────┐
         │ selector      │  → Finds the correct Pods
         └───────────────┘
                 │
                 ▼
         ┌───────────────┐
         │ ports         │  → Receives incoming request
         └───────────────┘
                 │
                 ▼
         ┌───────────────┐
         │ targetPort    │  → Sends request to application inside Pod
         └───────────────┘
                 │
                 ▼
         ┌───────────────┐
         │ type          │  → Decides how the Service is exposed
         └───────────────┘

apiVersion: v1
kind: Service

metadata:
  name: nginx-service

spec:
  selector:
    app: nginx

  ports:
  - port: 80
    targetPort: 80

  type: ClusterIP

========================================================================================================================
selector
========================================================================================================================

What    : selector is used by a Service to find the correct Pods. It matches the Labels of Pods and creates a group
          of Pods that should receive incoming requests.

Why     : A Kubernetes cluster can have hundreds of Pods running different applications. The Service must know
          exactly which Pods belong to its application. Without a selector, the Service would not know where to
          send incoming traffic.

How     : The Service compares its selector with the Labels of all Pods. If the Labels match, the Pod becomes part
          of the Service. If the Labels do not match, the Pod is ignored.

Think   : Think of a delivery boy delivering a parcel. He checks the flat number on every door and delivers the
          parcel only to the matching address. Similarly, a Service checks the Labels of every Pod and selects
          only the matching Pods.

Memory  : Selector Finds Pods.
          Labels Identify Pods.

========================================================================================================================
Important Points
========================================================================================================================
✔ Selector never creates Pods.
✔ Selector only finds matching Pods.
✔ Service uses Selector to route traffic.
✔ ReplicaSet also uses Selector, but to manage Pods.
✔ Matching Labels are mandatory.
✔ Pods without matching Labels never receive traffic from the Service.

========================================================================================================================
Interview Questions
========================================================================================================================
Q. What is a selector?
Ans: A selector is used by a Service to find the correct Pods by matching their Labels.

------------------------------------------------------------------------------------------------------------------------
Q. Why does a Service need a selector?
Ans: Because the Service must know which Pods should receive incoming traffic.

------------------------------------------------------------------------------------------------------------------------
Q. Does a selector create Pods?
Ans: No. Selector only finds matching Pods. ReplicaSet or Deployment creates Pods.

------------------------------------------------------------------------------------------------------------------------
Q. What happens if Labels and selector do not match?
Ans: The Service ignores those Pods, and traffic is not forwarded to them.

------------------------------------------------------------------------------------------------------------------------
Q. Do ReplicaSet and Service use selectors for the same purpose?
Ans: No. ReplicaSet uses selectors to manage Pods, whereas Service uses selectors to find Pods and route traffic.

========================================================================================================================
Common Beginner Mistakes
========================================================================================================================
❌ Selector creates Pods.
✔ ReplicaSet or Deployment creates Pods. Selector only finds them.

------------------------------------------------------------------------------------------------------------------------
❌ Service sends traffic to every Pod.
✔ Service sends traffic only to Pods whose Labels match the selector.

------------------------------------------------------------------------------------------------------------------------
❌ Labels are optional.
✔ Without matching Labels, the Service cannot identify the correct Pods.

========================================================================================================================
ports
========================================================================================================================

What    : ports is a list that defines the networking configuration of a Service. It tells Kubernetes which ports
          the Service should expose and where the incoming requests should be forwarded.

Why     : A Service needs networking information to receive requests and send them to the correct application
          running inside the Pods. This information is defined inside the ports section.

How     : The ports section contains one or more port mappings. Each mapping tells Kubernetes which Service Port
          should receive the request and which Pod Port should handle it.

Think   : Think of a Reception Desk.

          A visitor enters through the Reception Desk. The receptionist checks which room should receive the
          visitor and forwards them accordingly.

          ports works in a similar way by defining how requests enter the Service and where they should go.

Memory  : ports = Networking Configuration of the Service.

========================================================================================================================
Important Points
========================================================================================================================
✔ ports is mandatory in every Service.
✔ ports is a list, so multiple port mappings can be defined.
✔ Each entry inside ports contains values like port and targetPort.
✔ ports only defines networking information.
✔ Actual applications run inside Pods, not inside the Service.

========================================================================================================================
Interview Questions
========================================================================================================================
Q. What is ports in a Kubernetes Service?
Ans: ports defines the networking configuration of the Service and contains one or more port mappings.

------------------------------------------------------------------------------------------------------------------------
Q. Can a Service have multiple ports?
Ans: Yes. A Service can expose multiple ports by adding multiple entries under the ports section.

------------------------------------------------------------------------------------------------------------------------
Q. Does ports expose the application directly?
Ans: No. ports only defines the networking configuration. The application still runs inside the Pods.

========================================================================================================================
Common Beginner Mistakes
========================================================================================================================
❌ ports and port are the same.
✔ ports is a list, whereas port is one field inside that list.

------------------------------------------------------------------------------------------------------------------------
❌ ports runs the application.
✔ Pods run the application. ports only defines networking.

========================================================================================================================
Example
========================================================================================================================
Service

ports:
- port: 80
  targetPort: 8080

- port: 443
  targetPort: 8443

Result
✔ Service receives requests on Ports 80 and 443.
✔ Requests are forwarded to the respective application ports inside the Pods.
