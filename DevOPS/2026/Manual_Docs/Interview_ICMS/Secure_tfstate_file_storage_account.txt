


Q: How can you secure the Terraform tfstate file stored in an Azure Storage Account?


A:
I secure the Terraform state file using multiple layers:


1. Azure RBAC
   - I avoid using Storage Account access keys wherever possible.
   - I use Microsoft Entra ID / Managed Identity / Service Principal authentication.
   - Assign only the required RBAC role, such as:
       Storage Blob Data Contributor
   - This follows least-privilege access.

2. Private Endpoint
   - I can configure a Private Endpoint for the Storage Account.
   - This allows the Terraform backend to access the storage privately
     through the VNet instead of exposing the storage endpoint publicly.
   - Public network access can be disabled if the architecture allows it.

3. Storage Account Network Restrictions
   - Restrict public network access.
   - Allow only selected networks or private endpoints.
   - Use firewall/network rules where applicable.

4. Encryption
   - Azure Storage encrypts data at rest by default.
   - For stronger control, Customer-Managed Keys (CMK) can be used
     with Azure Key Vault.

5. Blob Versioning / Soft Delete
   - Enable Blob Versioning so previous versions of tfstate can be recovered.
   - Enable Blob Soft Delete to protect against accidental deletion.
   - This helps recover the state if it is accidentally modified or deleted.

6. State Locking / Concurrency
   - Terraform's AzureRM backend supports state locking.
   - This prevents multiple Terraform operations from modifying the
     same state simultaneously.

7. Access Control
   - Only the CI/CD identity and authorized administrators should have
     access to the state container.
   - Developers should not get unnecessary write access to the state.

8. Secure Authentication in CI/CD
   - Instead of storing Storage Account keys or client secrets in the
     pipeline, I prefer Microsoft Entra ID authentication.
   - OIDC / Federated Identity can be used so the pipeline can
     authenticate to Azure without storing long-lived credentials.

9. Sensitive Data
   - tfstate can contain sensitive information.
   - Therefore, I treat the state file as sensitive data and never commit
     it to Git.
   - I also avoid exposing the state file in pipeline logs.

10. Monitoring and Auditing
    - Enable Azure Monitor / diagnostic logging where required.
    - Monitor access to the Storage Account and investigate unauthorized
      access attempts.



Overall security:

   |
   | Entra ID / OIDC
   v
CI/CD Identity
   |
   | RBAC
   v
Azure Storage Account
   |
   +--> Private Endpoint / Network Restrictions
   |
   +--> Blob Container
   |      	|
   |      	+--> tfstate
   |
   +--> Encryption
   +--> Versioning
   +--> Soft Delete
   +--> Monitoring
