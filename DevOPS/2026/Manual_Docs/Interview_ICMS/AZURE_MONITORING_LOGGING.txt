1. LOG ANALYTICS WORKSPACE
----------------------------------------------------------------------------------------------------------------
Definition:
• Log Analytics Workspace is a centralized place where Azure Monitor log data is stored and queried.
Purpose:
• Collect logs from multiple Azure resources/subscriptions.
• Centralize logs for troubleshooting and monitoring.
• Query logs using KQL.
• Create log-based alerts.
Interview:
"Log Analytics Workspace provides a centralized location to collect, store and query logs from
Azure resources and other supported sources."
----------------------------------------------------------------------------------------------------------------
2. AZURE MONITOR
----------------------------------------------------------------------------------------------------------------
Definition:
• Azure Monitor is Azure's monitoring platform for collecting and analyzing metrics and logs.
Main capabilities:
• Metrics
• Logs
• Activity Logs
• Alerts
• Workbooks
• Insights
• Application monitoring
Simple difference:
Azure Monitor
     ↓
Overall monitoring platform
     ↓
Log Analytics Workspace
     ↓
Central place for log data
     ↓
KQL
     ↓
Query / Analyze logs
----------------------------------------------------------------------------------------------------------------
3. DIAGNOSTIC SETTINGS
----------------------------------------------------------------------------------------------------------------
Definition:
• Diagnostic Settings define which resource logs/metrics should be collected and where they should be
  sent.
Example:
Key Vault
   ↓
Diagnostic Settings
   ↓
Select required logs
   ↓
Log Analytics Workspace
Purpose:
• Send resource logs to Log Analytics.
• Send logs/metrics to supported destinations.
• Enable centralized monitoring.
Typical destinations:
→ Log Analytics Workspace
→ Storage Account
→ Event Hub
----------------------------------------------------------------------------------------------------------------
4. ACTIVITY LOG
----------------------------------------------------------------------------------------------------------------
Definition:
• Activity Log records subscription-level Azure management/control-plane operations.
Examples:
• VM created
• VM deleted
• NSG changed
• Resource Group deleted
• RBAC role assignment changed
• Resource configuration changed
Example:
User
  ↓
Deletes VM
  ↓
Azure Activity Log
  ↓
Event recorded
Important:
• Activity Log is different from resource logs.
• Activity Log = management-plane activity.
----------------------------------------------------------------------------------------------------------------
5. RESOURCE LOGS
----------------------------------------------------------------------------------------------------------------
Definition:
• Resource Logs contain information generated by a specific Azure resource/service.
Examples:
• Key Vault logs
• Application Gateway logs
• Azure Firewall logs
• AKS logs
• Storage logs
Difference:
Activity Log
   → What happened to Azure resources at subscription/control-plane level?
Resource Logs
   → What happened inside/at the service/resource level?
----------------------------------------------------------------------------------------------------------------
6. KQL — KUSTO QUERY LANGUAGE
----------------------------------------------------------------------------------------------------------------
Definition:
• KQL is used to query, filter and analyze log data in Log Analytics.
Used for:
• Troubleshooting
• Searching logs
• Finding failed operations
• Security investigation
• Creating log-based alerts
Basic structure:
TableName
| where condition
| project columns
| order by column
Example:
AzureActivity
| where ActivityStatusValue == "Failed"
| project TimeGenerated, Caller, OperationNameValue, ResourceGroup
| order by TimeGenerated desc
Common operators:
→ where      = filter
→ project    = select columns
→ summarize  = group/aggregate data
→ count()    = count records
→ order by   = sort
→ take       = limit results
→ ago()      = previous time period
----------------------------------------------------------------------------------------------------------------
7. ALERTS
----------------------------------------------------------------------------------------------------------------
Definition:
• Azure Monitor Alert automatically detects a defined condition and generates an alert.
Common types:
• Metric Alert
• Log Search / Log Alert
• Activity Log Alert
Example — Metric:
VM CPU > 80%
     ↓
Metric Alert Rule
     ↓
Action Group
     ↓
Email / Notification
Example — Activity Log:
Resource deleted
     ↓
Activity Log Alert
     ↓
Action Group
     ↓
Notification
Example — Log:
KQL query detects error condition
     ↓
Log Alert Rule
     ↓
Action Group
----------------------------------------------------------------------------------------------------------------
8. ACTION GROUP
----------------------------------------------------------------------------------------------------------------
Definition:
• Action Group defines what action should be taken when an alert is triggered.
Example:
Alert Rule
    ↓
Action Group
    ├── Email
    ├── SMS
    ├── Push notification
    ├── Webhook
    └── Other supported actions
Simple understanding:
Alert Rule
   = "When should I alert?"
Action Group
   = "What should I do after alert?"

11. HOW TO IMPLEMENT IN AZURE — PRACTICAL STEPS
----------------------------------------------------------------------------------------------------------------
STEP 1 — Management Subscription
• Create/use dedicated Management subscription.
• Keep centralized monitoring resources here.
STEP 2 — Resource Group
• Create:
  rg-monitoring
STEP 3 — Log Analytics Workspace
• Azure Portal
  → Log Analytics Workspaces
  → Create
  → Select Management Subscription
  → Select rg-monitoring
  → Give workspace name
  → Select region
  → Create
STEP 4 — Connect Azure Resources
Example:
Production Key Vault
  → Monitoring
  → Diagnostic Settings
  → Create Diagnostic Setting
  → Select required log categories
  → Destination = Log Analytics Workspace
  → Select central workspace
  → Save
STEP 5 — Configure Activity Log Collection
• Configure subscription Activity Logs to be sent to central Log Analytics Workspace.
• This allows centralized querying of management-plane activities.
STEP 6 — Create Alert Rules
• Azure Monitor
  → Alerts
  → Create Alert Rule
  → Select Scope
  → Configure Condition
  → Select Action Group
  → Create
STEP 7 — Create Action Group
• Define notification/action:
  → Email
  → Webhook
  → Other supported action
STEP 8 — Test
• Generate a test event.
• Check whether log appears in Log Analytics.
• Run KQL query.
• Trigger alert condition.
• Verify notification.

17. IMPORTANT KQL EXAMPLES
----------------------------------------------------------------------------------------------------------------
FAILED AZURE OPERATIONS:
AzureActivity
| where ActivityStatusValue == "Failed"
| project TimeGenerated, Caller, OperationNameValue, ResourceGroup
| order by TimeGenerated desc
----------------------------------------------------------------------------------------------------------------
LAST 1 HOUR:
AzureActivity
| where TimeGenerated > ago(1h)
| project TimeGenerated, Caller, OperationNameValue, ActivityStatusValue
| order by TimeGenerated desc
----------------------------------------------------------------------------------------------------------------
COUNT FAILED OPERATIONS:
AzureActivity
| where ActivityStatusValue == "Failed"
| summarize count()
----------------------------------------------------------------------------------------------------------------
FAILED OPERATIONS BY USER:
AzureActivity
| where ActivityStatusValue == "Failed"
| summarize FailedCount=count() by Caller
| order by FailedCount desc

18. IMPORTANT DIFFERENCES — INTERVIEW REVISION
----------------------------------------------------------------------------------------------------------------
Azure Monitor
→ Overall Azure monitoring platform.

→ Central store/query location for log data.

→ Language used to query/analyze log data.
Diagnostic Settings
→ Configure which resource logs/metrics are collected and where they are sent.

→ Subscription-level management/control-plane events.

19. COMMON INTERVIEW QUESTIONS
----------------------------------------------------------------------------------------------------------------
Q: Why do we use a Management Subscription?
A:
• To keep centralized management/monitoring resources separate from workloads.
• Provides centralized monitoring and operational visibility.
----------------------------------------------------------------------------------------------------------------
Q: What is Log Analytics Workspace?
A:
• Central location for collecting, storing and querying log data.
----------------------------------------------------------------------------------------------------------------
Q: What is Azure Monitor?
A:
• Azure's monitoring platform for metrics, logs, insights and alerts.
----------------------------------------------------------------------------------------------------------------
Q: How do you send resource logs to Log Analytics?
A:
• Configure Diagnostic Settings on the resource and select the Log Analytics Workspace as destination.
----------------------------------------------------------------------------------------------------------------
Q: How do you monitor multiple subscriptions?
A:
• Use centralized monitoring architecture.
• Send required logs from multiple subscriptions to a central Log Analytics Workspace.
• Use Azure Policy to enforce monitoring configuration at scale.
----------------------------------------------------------------------------------------------------------------
Q: What is KQL used for?
A:
• To query, filter and analyze logs in Log Analytics.
----------------------------------------------------------------------------------------------------------------
Q: Difference between Activity Log and Resource Logs?
A:
• Activity Log → subscription-level management/control-plane events.
• Resource Logs → logs generated by individual Azure services/resources.
----------------------------------------------------------------------------------------------------------------
Q: What is an Action Group?
A:
• It defines the notification/action to execute when an alert is triggered.
----------------------------------------------------------------------------------------------------------------
Q: How will you monitor 50 Azure subscriptions?
A:
Management Group
     ↓
Central Management Subscription
     ↓
Central Log Analytics Workspace
     ↓
Diagnostic Settings / Azure Policy
     ↓
Azure Monitor
     ↓
Alerts / Workbooks / KQL
