STEP 5: ADD rg-app ENTRY IN terraform.tfvars
----------------------------------------------------------------------------------------------------------------
File:
    environment/dev/terraform.tfvars

Configuration:
    rg_map = {
      rga = {
        name     = "rg-web"
        location = "central india"
      }
      rgtry = {
        name     = "rg-app"
        location = "central india"
      }
    }

Explanation:
    `rg_map` existing Resource Group module ka input map hai.
    `rga`   -> Existing Terraform-managed Resource Group `rg-web`.
    `rgtry` -> Azure mein existing Resource Group `rg-app` ke liye nayi Terraform configuration entry.

    `rgtry` map key hi Terraform resource address mein use hogi. Sirf variable entry add karne se Terraform normally
    resource create karne ka plan bana sakta hai; import block us existing resource ko state mein import karne ke
    liye mapping define karega.

NOTE:
    `rg_map` aur uska object structure tere existing module configuration ke according hai.

STEP 6: CREATE imports.tf FILE
----------------------------------------------------------------------------------------------------------------
File Path:
    environment/dev/import.tf

NOTE:
    `import.tf` koi fixed filename nahi hai. `imports.tf` bhi use kar sakte ho. Terraform working directory ki
    `.tf` configuration files automatically load karta hai.

Code:
    import {
      to = module.resource_group.azurerm_resource_group.RG["rgtry"]
      id = "/subscriptions/<SUBSCRIPTION_ID>/resourceGroups/rg-app"
    }

EXPLANATION:
    `to` = Terraform configuration mein target resource address.
           module.resource_group -> Root module mein child module ka naam.
           azurerm_resource_group.RG -> Child module ka resource address.
           ["rgtry"] -> terraform.tfvars mein define ki gayi map key.

    `id` = Azure mein pehle se existing `rg-app` ka Resource ID.

    Import block existing Azure resource ko Terraform resource address ke saath map karta hai.

STEP 7: RUN TERRAFORM PLAN
----------------------------------------------------------------------------------------------------------------
Command:
    terraform plan

EXPECTED OUTPUT:
    module.resource_group.azurerm_resource_group.RG["rgtry"]: Preparing import...
    [id=/subscriptions/<SUBSCRIPTION_ID>/resourceGroups/rg-app]

    Terraform will perform the following actions:

      # module.resource_group.azurerm_resource_group.RG["rgtry"] will be imported
        resource "azurerm_resource_group" "RG" {
            id         = "/subscriptions/<SUBSCRIPTION_ID>/resourceGroups/rg-app"
            location   = "centralindia"
            managed_by = null
            name       = "rg-app"
            tags       = {}
        }

    Plan: 1 to import, 0 to add, 0 to change, 0 to destroy.

EXPLANATION:
    `1 to import` -> Existing rg-app Terraform state mein import hoga.
    `0 to add`    -> Naya Azure Resource Group create nahi hoga.
    `0 to change` -> Koi infrastructure update planned nahi hai.
    `0 to destroy`-> Koi resource delete nahi hoga.

IMPORTANT:
    Agar plan mein unexpected create, update, replacement ya destroy action dikhe, toh apply karne se pehle
    configuration aur resource address verify karo.

IMPORTANT LEARNING
================================================================================================================
1. Traditional `terraform import` CLI command ke unlike, import block ko Terraform configuration mein define karte hain.
2. Import block kisi bhi suitable `.tf` file mein likh sakte hain; filename fixed nahi hai.
3. `terraform.tfvars` mein input variable values define hoti hain; import block wahan nahi likhte.
4. `for_each` use karte waqt target resource address mein correct map key dena zaroori hai.
5. Import block ke liye corresponding Terraform resource configuration available honi chahiye.
6. `terraform plan` import ko identify karta hai; `terraform apply` import operation execute karta hai.
7. Successful import ke baad bhi `terraform plan` run karke configuration aur state verify karna chahiye.
8. Enterprise production mein `-auto-approve` use karne se pehle approved plan aur change-control process follow karo.
