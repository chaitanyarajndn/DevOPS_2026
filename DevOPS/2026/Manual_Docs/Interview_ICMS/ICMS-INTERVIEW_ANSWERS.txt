"At a high level, the request starts when a user accesses the ICMS
application through the internet. The request reaches Application
Gateway, which acts as the main entry point for the application.

From there, the request reaches the application running on AKS.
In our environment, the application workloads are running across
Node 1 and Node 2, with Angular and .NET workloads running as Pods.

The Angular frontend handles the user interaction. When the frontend
needs information from the application, it communicates with the
.NET backend through the required API. The backend processes the
request and communicates with the database.

For the internal backend path, the required service can use the
Kubernetes Service and Internal Load Balancer so that the backend
service remains privately accessible.

The response then comes back from the backend to the frontend and
is presented to the user.

So the basic flow is User -> Internet -> Application Gateway ->
AKS -> Angular / .NET -> Database, with the internal service path
remaining private."

"At a high level, the Azure environment is implemented from the
approved HLD, LLD and IP planning provided by our Architect and
DevOps Architect team. My responsibility is to take that design and
deploy it correctly in the target Azure environment.

The overall network follows a Hub-Spoke model. The Hub VNet contains
the common connectivity and security components such as Azure Bastion,
Azure Firewall and VPN Gateway. The ICMS workload is maintained in
the Spoke VNet.

Inside the Spoke, the components are placed according to the
approved network design. Application Gateway has its own subnet,
AKS has its own subnet and Private Endpoints have their required
subnet. So Application Gateway and AKS are not placed inside the
same subnet.

The Hub and Spoke are connected through VNet Peering. From my side,
I take care of the implementation details such as the resource
configuration, network addressing from the IP planning, subnet
configuration, security controls and connectivity.

Once the infrastructure is deployed, I validate that the environment
matches the HLD and LLD and that the required connectivity is working
as expected.

So I would describe my role here as the implementation and deployment
of the approved Azure architecture. The architecture itself is
provided by the architecture team, and I make sure that the design
is correctly translated into a working Azure environment."

8. WHAT APPLICATION STACKS ARE RUNNING IN YOUR PROJECT?
------------------------------------------------------------

"The ICMS application has three main layers. The frontend is built
using Angular, the backend is developed using .NET and ASP.NET Core,
and then we have the database layer.

Angular handles the user-facing part of the application, while the
.NET backend provides the APIs and application service layer. The
backend communicates with the database, so the frontend does not
directly access the database.

From my side, I mainly work on the Azure environment in which these
application components are deployed. Once the infrastructure is
implemented and validated, the application components are deployed
on top of that environment.

So at a high level, the application stack is Angular for the frontend,
.NET / ASP.NET Core for the backend and the database as the data
layer."
