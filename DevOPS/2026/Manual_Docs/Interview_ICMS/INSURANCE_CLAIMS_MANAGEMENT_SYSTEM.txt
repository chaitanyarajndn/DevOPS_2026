1. PROJECT OVERVIEW — WHAT I WILL SAY IN INTERVIEW
------------------------------------------------------------
"I worked on an Insurance Claims Management System for a US-based insurance client. It was a .NET-based enterprise application used to manage the insurance claim lifecycle, starting from customer and policy information through claim registration, assessment and finally settlement or closure.

The project followed Agile methodology with two-week sprints. There were separate development, QA and DevOps teams. The development team was responsible for the application and database development, while my responsibility as a DevOps Engineer was mainly around Azure infrastructure, infrastructure automation, CI/CD and application deployments.

I worked on provisioning and managing Azure infrastructure using Terraform, maintaining Azure DevOps YAML pipelines, containerizing the application using Docker, storing images in Azure Container Registry and deploying the application workloads to Kubernetes. I was also involved in environment management, deployment validation, production troubleshooting, rollback activities and post-deployment support."



WHAT I WILL SAY:
"When a user accesses the application, the request first reaches the DNS endpoint and then comes through the application gateway. The gateway handles the incoming traffic and routes it towards the Kubernetes environment. Inside AKS, the request reaches the appropriate Kubernetes service and then the application pod. The backend then communicates with the required database or storage services."
IF INTERVIEWER ASKS "WHY APPLICATION GATEWAY?"
"Its role is to provide the application entry point and route HTTP or HTTPS traffic to the appropriate backend while providing features such as Web Application Firewall protection."

21. INTERVIEW STATEMENTS — ALL TOGETHER
==================================================================================================================
Q: "Tell me about your project."
A:
"I worked on an Insurance Claims Management System for a US-based insurance client. It is an enterprise .NET-based
application used to manage the insurance claim lifecycle. The project followed Agile methodology with two-week sprints,
and there were separate development, QA and DevOps teams.

The development team was responsible for application development, while I worked on the DevOps side. My responsibility
was mainly around Azure infrastructure provisioning, CI/CD automation, containerization, application deployment and
production support.

I used Terraform to provision and manage the required Azure infrastructure and Azure DevOps YAML pipelines to automate
the deployment process. For application deployment, I worked with Docker, Azure Container Registry and Kubernetes. I was
also involved in environment promotion, deployment validation, troubleshooting and rollback activities during releases."
------------------------------------------------------------------------------------------------------------------
Q: "What does your application do?"
A:
"The application is an Insurance Claims Management System used to manage the insurance claim lifecycle. At a high level,
a customer can access the system, submit an insurance claim and provide the required information and documents. The claim
then goes through validation and processing, and based on the outcome it moves towards settlement or closure."
------------------------------------------------------------------------------------------------------------------
Q: "What was your role in the project?"
A:
"I was responsible for the DevOps side of the application. The development team provided the application code, and my
responsibility was to build, package and deploy that application along with managing the Azure infrastructure required to
run it. I worked with Terraform, Azure DevOps, Docker, ACR and Kubernetes, and I was also involved in deployment
validation, production troubleshooting and rollback activities."
------------------------------------------------------------------------------------------------------------------
Q: "Did you develop the frontend or backend?"
A:
"No. The development team handled the application development. My responsibility started from the DevOps side, where I
worked on the CI/CD process, containerization, infrastructure and deployment of the application."
------------------------------------------------------------------------------------------------------------------
Q: "Explain your application deployment process."
A:
"Developers first raise a Pull Request for their application changes. After code review and approval, the changes are
merged into the target branch. This triggers the Azure DevOps pipeline, where we build and validate the application,
perform the required quality and security checks, create the Docker image and push it to Azure Container Registry. The
deployment stage then uses the required Kubernetes deployment configuration to deploy the image to AKS. After deployment,
we validate the application before promoting the release to the next environment."
------------------------------------------------------------------------------------------------------------------
Q: "Why is Pull Request part of your process?"
A:
"We don't directly deploy unreviewed application changes. Developers raise a Pull Request, the required code review and
approval takes place, and only after the changes are merged does the deployment pipeline proceed. This gives us a
controlled and traceable release process."
------------------------------------------------------------------------------------------------------------------
Q: "Explain Docker, ACR and AKS in your project."
A:
"We used Docker to package the application into a container image. Azure Container Registry was used as the private
registry to store those images, and Azure Kubernetes Service was used to run and orchestrate the containers. The pipeline
builds the image, pushes it to ACR and then deploys the required image version to AKS."
------------------------------------------------------------------------------------------------------------------
Q: "How did you provision the Azure infrastructure?"
A:
"We used Terraform for infrastructure provisioning. The Terraform code was maintained in Git and executed through Azure
DevOps pipelines. We validated the code, performed security checks, reviewed the Terraform plan and then applied the
approved changes to the required environment."
------------------------------------------------------------------------------------------------------------------
Q: "How did you deploy the same application across multiple environments?"
A:
"We maintained environment-specific deployment configuration while keeping the overall deployment process consistent.
The release was promoted through DEV, QA and UAT, followed by the required production approval before deploying to PROD."
------------------------------------------------------------------------------------------------------------------
Q: "What did you do after deployment?"
A:
"After deployment, I validated the pipeline status, Kubernetes deployment, pod health and application availability. If
there was an issue, I checked the deployment logs, pod status, container logs and Kubernetes events and worked with the
application team when the issue was application-related."
------------------------------------------------------------------------------------------------------------------
Q: "How did you troubleshoot a failed deployment?"
A:
"I first identified which layer was failing. I checked the pipeline logs, Kubernetes deployment status, pod status,
container logs and Kubernetes events. I also checked configuration or secret-related issues. Once the root cause was
identified, we either corrected the issue and redeployed or rolled back to the previous stable version."
------------------------------------------------------------------------------------------------------------------
Q: "What happens if a production deployment fails?"
A:
"We first assess the impact and identify the root cause. If the issue can be safely corrected, we fix the configuration
or deployment and redeploy. If the release cannot be safely fixed within the release window, we roll back to the previous
stable version and validate the application before considering the production issue resolved."
------------------------------------------------------------------------------------------------------------------
Q: "How much do you understand about the application?"
A:
"I understand the application from the deployment and runtime perspective. I know what the application does, what
components I need to deploy, how those components are packaged and deployed, and what dependencies or configuration are
required for the application to run. The detailed application business logic and development are handled by the
development team."
------------------------------------------------------------------------------------------------------------------
Q: "Why do you need to understand the business flow as a DevOps Engineer?"
A:
"I don't need to understand the business logic at the developer level, but I need to understand the high-level business
flow because it helps me understand what the application is doing, what functionality is affected during an incident and
what needs to be validated after a deployment. It also helps me communicate effectively with developers and QA during
production issues."
------------------------------------------------------------------------------------------------------------------
Q: "What is the main business flow?"
A:
"At a high level, a policyholder reports an incident and submits a claim. The application registers the claim and performs
the required validation and processing. Based on the claim decision, it moves towards settlement if approved or closure if
it is not approved. My responsibility is to deploy and maintain the application infrastructure supporting this workflow."
