🔷 WHAT IS A VARIABLE ?
───────────────────────────────────────────────────────────────────────
Terraform Variable is a placeholder used to store values
which can be dynamically reused inside Terraform code.

It helps infrastructure become:
✔ Dynamic
✔ Reusable
✔ Flexible
✔ Scalable
✔ Environment Independent

Simple Meaning:
Instead of hardcoding values directly inside resources,
Terraform stores values separately using variables.


═══════════════════════════════════════════════════════════════════════
                  🔷 WHY VARIABLES EXIST ?
═══════════════════════════════════════════════════════════════════════

Without Variables:

name = "rg-production"

Problems:
❌ Fixed values
❌ Difficult maintenance
❌ Repeated code changes
❌ Hard multi-environment handling
❌ Poor scalability

With Variables:

name = var.rg_name

Benefits:
✔ Same code reusable everywhere
✔ Only values change
✔ Better automation
✔ Cleaner infrastructure
✔ Faster deployments


═══════════════════════════════════════════════════════════════════════
                  🔷 REAL LIFE ANALOGY
═══════════════════════════════════════════════════════════════════════

Think of Variables like a blank form field.

Example:

Name : ___________

Field remains same.
Only entered value changes.

Terraform Variables work exactly same way.

var.rg_name can become:

DEV   → rg-dev
TEST  → rg-test
UAT   → rg-uat
PROD  → rg-prod

═══════════════════════════════════════════════════════════════════════
                  🔷 VARIABLE TYPES
═══════════════════════════════════════════════════════════════════════

1️⃣ STRING
Used for text values.

variable "rg_name" {

    type = string

}

2️⃣ NUMBER
Used for numeric values.

variable "vm_count" {

    type = number

}

3️⃣ BOOL
Used for true/false values.

variable "enable_backup" {

    type = bool

}

4️⃣ LIST
Stores multiple values.

variable "locations" {

    type = list(string)

}

5️⃣ MAP
Stores key-value pairs.

variable "tags" {

    type = map(string)

}


═══════════════════════════════════════════════════════════════════════
                  🔷 VARIABLE BLOCK STRUCTURE
═══════════════════════════════════════════════════════════════════════

Basic Syntax:

variable "variable_name" {

    type        = string
    default     = "value"
    description = "variable description"

}

Components:
✔ variable      → Terraform keyword
✔ variable_name → Actual variable identifier
✔ type          → Defines datatype
✔ default       → Fallback value
✔ description   → Variable explanation


═══════════════════════════════════════════════════════════════════════
                  🔷 COMMON VARIABLE ATTRIBUTES
═══════════════════════════════════════════════════════════════════════

1️⃣ type
Defines datatype.

2️⃣ default
Provides default value.

3️⃣ description
Explains variable purpose.

4️⃣ sensitive
Hides sensitive values.

Example:

variable "password" {

    sensitive = true

}

5️⃣ validation
Applies custom rules.

Example:

validation {

    condition     = length(var.rg_name) > 3
    error_message = "Name too short"

}

                  🔷 INTERNAL TERRAFORM UNDERSTANDING
═══════════════════════════════════════════════════════════════════════

Terraform internally replaces variable references
with actual values before resource creation.

Example:

name = var.rg_name

Internally becomes:

name = "rg-production"
