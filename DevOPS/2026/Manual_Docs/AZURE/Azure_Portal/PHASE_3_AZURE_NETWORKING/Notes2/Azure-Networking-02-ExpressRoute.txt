====================================================
Definition (30 sec)
====================================================

Azure ExpressRoute is a managed Azure networking service that provides a private, dedicated, high-bandwidth connection between an On-Premises network and Microsoft Azure without using the public Internet.

====================================================
Definition (1 min)
====================================================

Azure ExpressRoute is a managed Azure networking service that establishes private connectivity between an organization's On-Premises infrastructure and Microsoft Azure through a connectivity provider. Traffic travels over the Microsoft Global Backbone instead of the public Internet, providing higher reliability, lower latency and better security.

====================================================
Problem
====================================================

VPN Gateway uses the public Internet.

Although the traffic is encrypted, some organizations such as banks, telecom companies, government agencies and healthcare providers require a private, dedicated and highly reliable connection to Azure.

====================================================
Solution
====================================================

Deploy Azure ExpressRoute.

ExpressRoute creates a private dedicated circuit between the On-Premises network and Microsoft Azure through an approved connectivity provider.

Traffic never travels over the public Internet.

====================================================
Components
====================================================

• ExpressRoute Circuit
  Private dedicated circuit between Microsoft and the customer.

• Connectivity Provider
  Microsoft-approved ISP or telecom provider that delivers the physical connection.

• Microsoft Edge POP
  Entry point where customer traffic enters Microsoft's global network.

• Microsoft Global Backbone
  Microsoft's private worldwide fiber network.

• ExpressRoute Gateway
  Azure gateway deployed inside the VNet to receive ExpressRoute traffic.

====================================================
Prerequisites
====================================================

• Azure Virtual Network
  ExpressRoute Gateway must be deployed inside a VNet.

• GatewaySubnet
  Create a dedicated subnet named exactly "GatewaySubnet".
  Azure deploys the ExpressRoute Gateway inside this subnet.

• ExpressRoute Circuit
  Must be created before configuring the gateway connection.

• Connectivity Provider
  A Microsoft-approved provider is required to establish the dedicated circuit.

• ExpressRoute Gateway SKU
  Select the appropriate gateway SKU based on throughput requirements.

====================================================
Post Configuration
====================================================

Azure automatically:

• Deploys the ExpressRoute Gateway inside GatewaySubnet.
• Connects the VNet to the ExpressRoute Circuit.
• Routes traffic through Microsoft Global Backbone.

Azure does NOT:

• Provision the physical circuit.
• Configure the connectivity provider.

These tasks must be completed by the service provider.

====================================================
Best Practices
====================================================

• Use ExpressRoute for production workloads.
• Deploy redundant circuits for high availability.
• Choose the appropriate bandwidth.
• Use ExpressRoute FastPath when supported.
• Monitor circuit utilization.
• Use Gateway Transit when multiple VNets require the same circuit.

====================================================
Important
====================================================

• ExpressRoute does NOT use the public Internet.
• Traffic travels over Microsoft's private Global Backbone.
• GatewaySubnet is mandatory.
• ExpressRoute Gateway is different from VPN Gateway.
• Physical connectivity is provided by a Microsoft-approved connectivity provider.

====================================================
Cost Note
====================================================

• ExpressRoute is significantly more expensive than VPN Gateway.
• Billing includes the ExpressRoute Circuit, bandwidth and gateway.
• Additional charges may apply from the connectivity provider.

====================================================
Common Mistakes
====================================================

• Assuming ExpressRoute uses the Internet.
• Forgetting to create GatewaySubnet.
• Confusing ExpressRoute Circuit with ExpressRoute Gateway.
• Selecting an incorrect bandwidth.
• Not provisioning redundancy for production workloads.

====================================================
Troubleshooting
====================================================

Problem
ExpressRoute Connection is not established.

Possible Reason

• Circuit not provisioned.
• Connectivity Provider configuration incomplete.
• Gateway not linked to the circuit.

Solution

Verify:

• Circuit provisioning status.
• Provider activation.
• Gateway configuration.
• VNet link.

====================================================
VPN Gateway vs ExpressRoute
====================================================

VPN Gateway
• Uses Public Internet
• Encrypted IPSec/IKE Tunnel
• Lower Cost
• Faster to Deploy
• Suitable for Small & Medium Workloads

ExpressRoute
• Uses Microsoft Global Backbone
• Private Dedicated Circuit
• Higher Cost
• Enterprise Grade
• Suitable for Mission-Critical Workloads
