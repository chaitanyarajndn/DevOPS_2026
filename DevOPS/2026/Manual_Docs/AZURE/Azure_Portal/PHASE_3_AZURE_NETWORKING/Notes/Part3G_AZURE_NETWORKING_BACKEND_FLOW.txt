SECTION-2 : VNET (VIRTUAL NETWORK)
============================================================

• Overview

Azure Virtual Network (VNet) is the foundational networking service in Azure.

It provides a private network boundary for Azure resources.

All Azure networking components operate inside a VNet.

------------------------------------------------------------

• Deployment Location

Created at Subscription level.

Subnets are created inside a VNet.

Virtual Machines, Private Endpoints, Gateways and other networking resources are deployed inside a VNet.

------------------------------------------------------------

• How It Works

Provides a private IP address space.

Enables communication between Azure resources.

Creates isolation from other networks.

------------------------------------------------------------

• When To Use

Application Hosting

Multi-Tier Architectures

Hybrid Connectivity

Enterprise Cloud Deployments

------------------------------------------------------------

• Business Purpose

Provides network isolation.

Establishes a secure communication boundary.

Acts as the foundation for enterprise network design.

------------------------------------------------------------

• Traffic Capabilities

Allow Traffic?      No

Deny Traffic?       No

Inspect Traffic?    No

Route Traffic?      No

------------------------------------------------------------

• Important Clarification

A VNet does not filter traffic.

A VNet does not inspect traffic.

A VNet does not route traffic.

A VNet only provides the network boundary.

------------------------------------------------------------

• Enterprise Example

India Region VNet

10.10.0.0/16

Contains:

Hub Subnet

Production Subnet

Development Subnet

QA Subnet

Management Subnet

------------------------------------------------------------

• Easy Memory Point

VNet = City

Everything else is built inside the city.

------------------------------------------------------------

• Flow Diagram

Azure Subscription
        │
        ▼

🌐 VNet
        │
        ▼

📦 Subnets
        │
        ▼

🖥️ Azure Resources

------------------------------------------------------------

• Interview Point

VNet is a logical network boundary and not a physical network.

SECTION-3 : SUBNET
============================================================

• Overview

A Subnet is a logical network segment created inside a VNet.

It divides a large network into smaller manageable sections.

Each subnet is assigned a portion of the VNet address space.

------------------------------------------------------------

• Deployment Location

Created inside a VNet.

Virtual Machines and services are deployed into subnets.

NSGs and Route Tables are commonly associated with subnets.

------------------------------------------------------------

• How It Works

Partitions the VNet address space.

Separates workloads into different network zones.

Provides workload-level segmentation.

------------------------------------------------------------

• When To Use

Web Tier

Application Tier

Database Tier

Management Tier

Shared Services Tier

------------------------------------------------------------

• Business Purpose

Improves organization.

Supports security boundaries.

Simplifies traffic control and management.

------------------------------------------------------------

• Traffic Capabilities

Allow Traffic?      No

Deny Traffic?       No

Inspect Traffic?    No

Route Traffic?      No

------------------------------------------------------------

• Important Clarification

A Subnet does not block traffic.

A Subnet does not inspect traffic.

A Subnet does not route traffic.

Traffic control happens through NSGs and Route Tables.

------------------------------------------------------------

• Enterprise Example

VNet

10.10.0.0/16

Web Subnet
10.10.1.0/24

Application Subnet
10.10.2.0/24

Database Subnet
10.10.3.0/24

SECTION-6 : NETWORK SECURITY GROUP (NSG)
============================================================

• Overview

Azure Network Security Group (NSG) is the primary traffic filtering service in Azure.

It controls inbound and outbound traffic using allow and deny rules.

It acts as the first security layer for Azure workloads.

------------------------------------------------------------

• Deployment Location

Subnet Level

Network Interface (NIC) Level

Most enterprises deploy NSGs at subnet level for centralized management.

------------------------------------------------------------

• How It Works

A packet reaches the subnet or NIC.

NSG evaluates rules based on priority.

The first matching rule is applied.

Traffic is either allowed or denied.

------------------------------------------------------------

• When To Use

Web Tier Protection

Application Tier Protection

Database Tier Protection

East-West Traffic Control

North-South Traffic Control

------------------------------------------------------------

• Business Purpose

Restrict unauthorized communication.

Implement least-privilege networking.

Reduce attack surface.

Protect workloads from unwanted traffic.

------------------------------------------------------------

• Traffic Capabilities

Allow Traffic?      Yes

Deny Traffic?       Yes

Inspect Traffic?    No

Route Traffic?      No

------------------------------------------------------------

• What NSG Can Check

Source IP

Destination IP

Port Number

Protocol

Direction

------------------------------------------------------------

• What NSG Cannot Check

Website URL

Application Content

Threat Intelligence

Malware Signatures

------------------------------------------------------------

• Easy Meaning

Traffic Filtering

That means deciding which traffic should be allowed and which traffic should be blocked.

Example:
Allow HTTPS traffic.
Block SSH traffic from the Internet.

------------------------------------------------------------

• Example Rule

Source      = Internet

Destination = Web Subnet

Port        = 443

Action      = Allow

------------------------------------------------------------

• NSG Success Flow

🌍 Internet User
        │
        ▼
🛡️ NSG
        │
        ▼
✅ Rule Matched
        │
        ▼
🖥️ Web Server

------------------------------------------------------------

• NSG Block Flow

🌍 Internet User
        │
        ▼
🛡️ NSG
        │
        ▼
❌ Deny Rule Matched
        │
        ▼
🚫 Packet Dropped

------------------------------------------------------------

• Enterprise Example

Web Subnet

Allow TCP 443

Allow TCP 80

Deny All Other Inbound Traffic

------------------------------------------------------------

• Easy Memory Point

NSG = Security Guard

Checks ID card.

Allows or denies entry.

Does not inspect luggage.

------------------------------------------------------------

• Interview Point

NSG provides traffic filtering but does not perform deep packet inspection.

Custom Network Paths

Traffic Steering

Hybrid Connectivity

------------------------------------------------------------

• Business Purpose

Force traffic inspection.

Implement enterprise routing strategy.

------------------------------------------------------------

• Traffic Capabilities

Deny Traffic?       No

Inspect Traffic?    No

Route Traffic?      Yes

Redirect Traffic

Control Traffic Path

Block Packets

Analyze Traffic

Perform Security Checks

------------------------------------------------------------
