============================================================
Azure_Service_Principal (Basic)
============================================================

Meaning
-------
Service Principal is a non-human identity in Microsoft Entra ID used by applications, automation tools and scripts to authenticate and access Azure resources.

Examples : Terraform | Azure DevOps | GitHub Actions | Jenkins | Ansible | Python Scripts

User               → Human Identity
Service Principal  → Application Identity

=========================================================
Why Service Principal?
=========================================================

Local Development
-----------------
	You
	 │
	 ▼
  az login
	 │
	 ▼
  Terraform
	 │
	 ▼
	Azure

Terraform uses YOUR Azure login (Azure CLI token).

Production / Automation
-----------------------
Azure DevOps Pipeline
        │
        ▼
Service Principal
        │
        ▼
	  Azure

No human login, browser or MFA required.

==========================================================================================================
What is App Registration?
==========================================================================================================

Azure doesn't know the identity of an application.

So first we REGISTER the application inside Microsoft Entra ID.

Microsoft Entra ID
        │
        ▼
App Registrations
        │
        ▼
New Registration
        │
        ▼
Application Registered

Example Names
-------------
terraform-prod
azuredevops-prod
github-actions
jenkins-prod

(Name is only a display name.)

==========================================================================================================
What Happens After Clicking Register?
==========================================================================================================

App Registration
        │
        ├─────────────────────┐
        │                     │
        ▼                     ▼
Application Object      Service Principal

Azure automatically creates the Service Principal.

You DO NOT create the Service Principal manually.

==========================================================================================================

These credentials are used by automation tools to authenticate with Azure.

==========================================================================================================
Important Interview Points
==========================================================================================================

✔ Service Principal is NOT an Azure Resource.
✔ Service Principal is an Identity in Microsoft Entra ID.
✔ Every automation tool should use its own Service Principal.
✔ RBAC controls what the Service Principal can access.
✔ Local Terraform usually uses "az login".
✔ Production CI/CD uses Service Principal.

Interview One-Liner
-------------------
A Service Principal is a non-human identity in Microsoft Entra ID that allows applications and automation tools such as Terraform or Azure DevOps to securely authenticate and access Azure resources based on assigned RBAC permissions.

=========================================
AZURE SERVICE PRINCIPAL (AZURE CLI)
=========================================

Create Service Principal

az ad sp create-for-rbac --name "gitlab-terraform-sp" --role Contributor --scopes /subscriptions/<SUBSCRIPTION_ID>

Example

az ad sp create-for-rbac --name "gitlab-terraform-sp" --role Contributor --scopes /subscriptions/a8c86d5d-e77e-4744-9758-f7cc3b1f2f9b

---------------------------------------------------------
Output
---------------------------------------------------------

appId        → ARM_CLIENT_ID
password     → ARM_CLIENT_SECRET
tenant       → ARM_TENANT_ID
Subscription → ARM_SUBSCRIPTION_ID

---------------------------------------------------------
Verify Service Principal
---------------------------------------------------------

az ad sp list --display-name "gitlab-terraform-sp" --output table

---------------------------------------------------------
Generate New Client Secret (Rotate Secret)
---------------------------------------------------------

az ad app credential reset --id <APP_ID>

Example

az ad app credential reset --id 110ad3bf-ffed-4a06-948b-0a629d0ead83

---------------------------------------------------------
Delete Service Principal
---------------------------------------------------------

az ad sp delete --id <APP_ID>

Example

az ad sp delete --id 110ad3bf-ffed-4a06-948b-0a629d0ead83

---------------------------------------------------------
GitLab CI/CD Variables
---------------------------------------------------------

ARM_CLIENT_ID         = appId
ARM_CLIENT_SECRET     = password
ARM_TENANT_ID         = tenant
ARM_SUBSCRIPTION_ID   = Azure Subscription ID

Purpose

Redirect URI
==========================================================================================================

Meaning
-------
After successful login, Microsoft Entra ID sends the user back to this URL.


Flow
----
User
 │
 ▼
Application
 │
 ▼
Microsoft Entra ID Login
 │
Authentication Success
 ▼
Redirect URI
 │
 ▼
Application

Example
-------
https://mycompany.com/auth

User logs in
      │
      ▼
Microsoft Entra ID
      │
      ▼
https://mycompany.com/auth

The application receives the authentication response here.

Application (Client) ID vs Object ID vs Tenant ID vs Client Secret
==========================================================================================================

Application (Client) ID
-----------------------
Meaning
-------
Unique ID of the registered application.

Think As
--------
Application Username

Used By
-------
✔ Terraform
✔ Azure DevOps
✔ GitHub Actions
✔ Azure CLI

Example
-------
App Name : terraform-prod

Application (Client) ID
        │
        ▼
Used to identify "Which application is requesting access?"

==========================================================================================================

Object ID
---------
Meaning
-------
Unique ID of the actual object stored inside Microsoft Entra ID.

Think As
--------
Internal Database Record ID

Every object has an Object ID.

Examples
--------
✔ User
✔ Group
✔ Service Principal
✔ App Registration
✔ Managed Identity

Interview Point
---------------
Object ID identifies the object itself, while Client ID identifies the application.

==========================================================================================================

Tenant ID
---------
Meaning
-------
Unique ID of your Microsoft Entra ID directory.

Think As
--------
Company Identity

Example
-------
ABC Company
      │
      ▼
Microsoft Entra ID
      │
      ▼
Tenant ID

Use
---
Azure needs to know which tenant should authenticate the request.

==========================================================================================================

Client Secret
-------------
Meaning
-------
Secret password of the application.

Think As
--------
Application Password

Example
-------
Application (Client) ID  → Username
Client Secret            → Password

Never expose or commit the Client Secret to Git repositories.

Application Registration vs Service Principal vs Enterprise Application
==========================================================================================================

Application Registration
------------------------
Meaning
-------
Defines the application inside Microsoft Entra ID.

Stores
------
✔ Application Name
✔ Client ID
✔ Redirect URI
✔ API Permissions
✔ Certificates / Client Secret

Think As
--------
Blueprint / Definition of the Application.

==========================================================================================================

Service Principal
-----------------
Meaning
-------
Identity created for the application to authenticate and access Azure resources.

Stores
------
✔ Object ID
✔ RBAC Permissions
✔ Role Assignments

Think As
--------
Identity Card of the Application.

==========================================================================================================

Enterprise Application
----------------------
Meaning
-------
Enterprise Application is simply the Service Principal shown from the Enterprise Applications blade.

Purpose
-------
Used by administrators to manage:

✔ Users & Groups
✔ Permissions
✔ SSO
✔ Conditional Access
✔ Sign-in Logs

Think As
--------
Management View of the Service Principal.
